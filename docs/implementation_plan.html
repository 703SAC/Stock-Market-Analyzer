Stock Market Analyzer 구현 계획

한국투자증권 Open API 샘플과 kis-ai-extensions를 각각 원재료 창고와 AI 개발 보조 도구로 두고, 거래량/상한가 스크리너부터 DART, 차트 조건식, 실시간 알림까지 확장 가능한 분석 앱으로 키우는 계획입니다.

먼저 결론

추천: open-trading-api는 submodule로 두고, 내 앱은 별도 app/에 만든다.

비유하면 한국투자증권 샘플은 공구함이고, kis-ai-extensions는 공구를 안전하게 쓰는 작업 지침서입니다. 공구함을 뜯어고치기보다, 작업대인 app/에서 필요한 공구와 지침만 골라 쓰는 방식이 좋습니다.

Fork vs Submodule

Submodule이 맞는 이유

추천

현재 필요한 기능은 원본 샘플을 고치는 일이 아니라, volume_rank, capture_uplowprice, chk_holiday 같은 함수를 감싸서 내 웹 서비스에서 쓰는 일입니다.

원본이 업데이트되면 submodule만 갱신하고, 내 앱 코드는 안정적으로 유지할 수 있습니다.

Fork가 필요한 경우

예외

원본 샘플 자체에 버그가 있어 직접 고쳐야 하거나, 한국투자증권 API 호출 방식 자체를 크게 바꿔야 한다면 fork를 검토합니다.

지금은 fork보다 adapter 계층을 두는 편이 더 깔끔합니다.

kis-ai-extensions 검토 결과

무엇인가?

개발 보조

kis-ai-extensions는 KIS Open API를 AI agent가 더 안전하게 쓰도록 돕는 플러그인/스킬/명령 모음입니다.

Codex, Claude, Cursor, Gemini용 설정과 /kis-setup, /auth, /my-status 같은 명령, 인증/환경 점검 스크립트가 들어 있습니다.

어떻게 쓸까?

활용

앱 런타임에 직접 import하지 않고, 개발 자동화와 안전 규칙, 인증 점검, 향후 전략/백테스트 확장 참고 자료로 씁니다.

즉, open-trading-api는 데이터 공구함, kis-ai-extensions는 AI 작업자용 안전 매뉴얼입니다.

구성 확인한 내용 우리 계획 반영
shared/scripts auth.py, do_auth.py, setup_check.py, api_client.py 인증 상태 확인, 환경 진단, 민감정보 비노출 패턴을 참고합니다.
shared/skills 전략 빌더, 백테스터, 주문 실행, 고객지원 스킬 차트 조건식 DSL과 향후 백테스트 기능 설계에 참고합니다.
shared/hooks secret guard, prod guard, trade log, MCP log 템플릿 API 키 노출 방지, 실전 주문 보호, agent 안전 규칙에 반영합니다.
agents/* Codex/Gemini/Claude/Cursor별 설정과 명령 다른 AI agent에게 구현을 맡길 때 프롬프트와 작업 규칙으로 활용합니다.

핵심 코드 패턴

확장 기능이 늘어도 흔들리지 않게, 모든 기능은 같은 길을 지나가게 만듭니다.

화면사용자가 날짜, 종목, 조건식을 입력합니다.
Router입력을 검증하고 서비스에 넘깁니다.
Feature기능 흐름을 조립합니다.
AdapterKIS, DART, 뉴스, LLM을 감쌉니다.
Model표준 데이터로 저장하고 응답합니다.

규칙 한 줄

라우터에서 외부 API를 바로 부르지 않습니다. 항상 router -> feature service -> adapter -> external API 순서로 갑니다.

frontend page
  -> backend router
    -> features/screener/service.py
      -> services/kis/adapter.py
        -> open-trading-api

kis-ai-extensions는 이 호출 경로 안에 넣지 않습니다. 대신 agent 작업 규칙, 인증 진단, secret/prod guard, 전략/백테스트 참고 자료로 씁니다.

코드베이스에서 쓸 재료

필요한 일 기존 코드 후보 계획
거래량 1000만 주 이상 종목 찾기 examples_user/domestic_stock/domestic_stock_functions.py의 volume_rank KisMarketAdapter.get_volume_rank()로 감싸고 내부 표준 모델로 변환합니다.
상한가 종목 찾기 capture_uplowprice fid_prc_cls_code="0"로 상한가 종목을 가져오고 이벤트 태그를 붙입니다.
거래일 범위 처리 chk_holiday 휴장일을 제외해 실제 장이 열린 날짜만 조회합니다.
가격/차트 데이터 inquire_daily_itemchartprice, get_daily_prices 보고서와 차트 조건식 검색의 공통 데이터로 사용합니다.
웹 UI strategy_builder의 FastAPI + Next.js 구조 기존 패턴을 참고하되, 분석 앱은 별도 app/에서 만듭니다.

기능 지도

1. 거래량/상한가 스크리너

MVP

날짜 또는 기간을 입력하면 거래량 1000만 주 이상 종목과 상한가 종목을 표로 보여줍니다.

주요 재료: volume_rank, capture_uplowprice, chk_holiday

2. 기사 검색

MVP

스크리너 결과 종목 또는 직접 입력 종목에 대해 기준일과 전일 기사를 모읍니다.

후보: Naver Search API, RSS, httpx, trafilatura

3. LLM 정형 보고서

MVP

가격 데이터와 기사를 넣고, 짧고 정해진 양식의 보고서를 생성합니다.

LLM 응답은 JSON Schema로 검증합니다.

4. DART 보고서 섹션

다음 단계

사업보고서/분기보고서에서 관심 섹션만 웹에서 따로 볼 수 있게 합니다.

공시 목록 조회는 쉽지만, 섹션 추출은 구체화가 필요합니다.

5. 차트 조건식 검색

다음 단계

일봉 데이터를 가져와 조건식을 평가하고, 만족한 날짜를 차트에 표시합니다.

처음에는 Python 실행 대신 안전한 JSON DSL을 씁니다.

6. 실시간 Telegram 알림

후반 단계

장중 조건식이 만족되면 Telegram으로 알림을 보냅니다.

조건식 엔진이 안정된 뒤 WebSocket 모니터링을 붙입니다.

추가 기능 난이도 판단

기능 난이도 이번 계획 반영 방식 더 정해야 할 것
DART 보고서 + 종합 분석 중간 폴더/adapter/스프린트까지 포함. 실제 구현은 Sprint 5~6. 관심 섹션 목록, 리서치 리포트 API 공급자, 원문 저장 정책
차트 조건식 + LLM 조건식 생성 중간~높음 JSON DSL과 evaluator 구조를 포함. 실제 구현은 Sprint 7~8. 검색 대상, 일봉/분봉 범위, 지원 지표 목록
실시간 모니터링 + Telegram 중간~높음 데이터 모델과 adapter 구조만 먼저 고려. 실제 구현은 Sprint 9. 감시 종목 수, 알림 빈도 제한, 서버 상시 실행 환경

데이터 모델 방향

StockIdentity

종목코드, 종목명, 시장을 담는 가장 작은 단위입니다.

모든 기능이 같은 종목 모델을 씁니다.

TradingDayStockEvent

특정 날짜에 어떤 종목이 어떤 조건을 만족했는지 기록합니다.

예: 거래량 폭증, 상한가, 조건식 만족

AnalysisReport

기사, 가격, DART, 차트 분석 결과를 같은 보고서 모델로 저장합니다.

보고서 타입: 뉴스/가격, DART, 차트, 종합

LLM 사용 규칙

LLM은 길게 말하는 해설자가 아니라, 정해진 양식에 맞춰 메모를 작성하는 도우미로 씁니다.

{
  "summary": "한 문장 요약",
  "key_points": ["핵심 근거 1", "핵심 근거 2"],
  "possible_reasons": ["가능한 이유"],
  "risks": ["주의점"],
  "confidence": "LOW|MEDIUM|HIGH"
}

투자 조언처럼 단정하지 않고, 출처가 기사인지 DART인지 가격 데이터인지 구분합니다.

스프린트 계획

Sprint 0: 프로젝트 뼈대와 패턴 확정

app/backend, app/frontend 생성, adapter 패턴, 공통 모델, 환경 변수, KIS 인증 연결을 잡습니다. kis-ai-extensions의 setup/auth/secret guard/prod guard 개념도 개발 체크리스트에 반영합니다.

Sprint 1: 거래량/상한가 스크리너

거래일 계산, volume_rank, capture_uplowprice adapter, SQLite 캐시, 결과 API를 만듭니다.

Sprint 2: 웹 UI 1차

날짜 선택, 결과 테이블, 조건 필터, CSV 다운로드, 로딩/에러 상태를 구현합니다.

Sprint 3: 기사 검색

뉴스 adapter, 중복 제거, 날짜 필터, 기사 선택 UI, 기사 캐시를 만듭니다.

Sprint 4: LLM 뉴스/가격 보고서

LLM adapter, JSON Schema 검증, 뉴스+가격 프롬프트, 보고서 저장과 카드 UI를 만듭니다.

Sprint 5: DART 1차

OpenDART API 키, corp_code 매핑, 공시 목록 조회, 원문 접근을 구현합니다.

Sprint 6: DART 섹션 추출 + 종합 보고서

관심 섹션 추출, 섹션 선택 UI, DART+가격+뉴스 종합 프롬프트를 만듭니다.

Sprint 7: 차트 조건식 MVP

일봉 데이터, 기본 지표, JSON DSL, 조건식 evaluator, 조건 만족 날짜 표시를 구현합니다.

Sprint 8: LLM 조건식 생성

자연어를 JSON DSL로 변환하고, 검증 후 실행할 수 있게 만듭니다.

Sprint 9: 실시간 모니터링 + Telegram

KIS WebSocket, monitor engine, 중복 알림 방지, Telegram 테스트 발송과 알림 로그를 구현합니다.

구현자가 지켜야 할 규칙

하지 말 것

금지 원본 open-trading-api를 대량 수정하지 않습니다.

금지 kis-ai-extensions를 앱 런타임 핵심 의존성으로 직접 import하지 않습니다.

금지 사용자가 입력한 Python 코드를 그대로 실행하지 않습니다.

금지 API 키를 프론트엔드에 노출하지 않습니다.

해야 할 것

필수 외부 API 호출은 timeout, retry, rate limit을 둡니다.

필수 같은 날짜/종목 결과는 캐시를 먼저 확인합니다.

필수 테스트는 외부 API mock 중심으로 작성합니다.

최종 추천 아키텍처

Submodule open-trading-api는 원본 공구함으로 둡니다.

Agent Tooling kis-ai-extensions는 개발 agent용 인증/진단/안전 규칙과 전략/백테스트 참고 자료로 둡니다.

Adapter KIS, 뉴스, DART, LLM, Telegram은 모두 services/*/adapter.py로 감쌉니다.

Feature Service 스크리너, 보고서, 차트, 모니터링 흐름은 features/*/service.py에 둡니다.

Cache 날짜별 검색 결과, 기사, DART 원문, LLM 보고서는 저장소에 캐시합니다.

실시간은 후반 실시간 Telegram 알림은 조건식 엔진이 안정된 뒤 붙입니다.
